# V04.5.1 X06 Forward-Migration Note

**Status:** Planning note for the V04.5.1 schema candidate only. No migration has been authored or applied, and no database was inspected.

## Observed contract mismatch

The V04.5.1 candidate schema specifies `ON DELETE RESTRICT` and `ON UPDATE RESTRICT` for both `Session.user → User` and `Account.user → User`.

The immutable migration history currently specifies a different update action:

- `20261106010425_phase_0_3_v03_better_auth_identity` initially creates both foreign keys with `ON DELETE CASCADE ON UPDATE CASCADE`.
- `20261106090000_p05_x06_restrict_auth_user_deletion` replaces both constraints with `ON DELETE RESTRICT ON UPDATE CASCADE`.

Therefore, replaying the checked-in history alone does not produce the candidate schema's `ON UPDATE RESTRICT` behavior. This is a source-level migration-history/schema-target mismatch; it does not establish the state of any deployed database.

## Forward-only migration requirement

If the V04.5.1 `RESTRICT`/`RESTRICT` target is retained and migration work is separately authorized, add a new migration after the existing X06 migration. Preserve all applied migration files and checksums. The new migration should replace both auth-user foreign keys so the final actions are `ON DELETE RESTRICT ON UPDATE RESTRICT`, retaining the existing constraint names unless inspection of the target database demonstrates otherwise.

Before authoring or applying that migration:

1. Confirm the intended target database's applied migration history and inspect both actual foreign-key definitions; do not infer deployed state from repository files.
2. Review user-ID update call paths and operational/locking implications of removing update cascades. User identifiers should be treated as immutable where required by the approved identity policy.
3. Generate and review the migration with the pinned Prisma CLI, then test both clean replay of the complete history and upgrade from the existing six-migration baseline on disposable PostgreSQL.
4. Verify both constraints' ordered columns and delete/update actions from PostgreSQL catalog metadata, and exercise both prohibited deletion and referenced-key-update cases.

The migration is not part of the current schema-only change. Do not edit historical migrations, connect to a database, or apply a migration as part of this candidate verification. Reconcile older documentation that describes X06 as `RESTRICT`/`CASCADE` only through a separately reviewed documentation update.
