## 2. Catalog and mapping assertions

Read-only preflight was performed independently on fresh and staged targets. Both reported PostgreSQL 17.6 and confirmed:

- `core.user.id` is non-null `TEXT`.
- `core.organization.id` is non-null `UUID`.
- `core.organization_membership.id` is non-null `UUID`.
- `core.organization_membership.userId` is non-null `TEXT`.
- `core.organization_membership.organizationId` is non-null `UUID`.
- `core.organization_membership.status` is non-null enum `core."OrganizationMembershipStatus"`.
- `organization_membership_userId_fkey` directly references `core."user"(id)`.
- `organization_membership_organizationId_fkey` directly references `core.organization(id)`.
- Both FKs are validated (`convalidated = true`) and use `ON UPDATE RESTRICT ON DELETE RESTRICT` (`confupdtype = r`, `confdeltype = r`).

The membership indexes included:

- `organization_membership_user_slot_key`: unique on `("userId")` with predicate `status IN ('ACTIVE', 'SUSPENDED')`.
- `organization_membership_id_user_org_key`: unique on `(id, "userId", "organizationId")`.
- `organization_membership_organizationId_status_idx`.
- `organization_membership_userId_status_idx`.
- Primary key on `id`.

The enum labels on both targets were `PENDING`, `ACTIVE`, `SUSPENDED`, `REVOKED`, and `ENDED`. No fresh/staged catalog discrepancy was reported.

## 3. Transactional behavior assertions

Each target was tested independently using one unique User fixture, three Organization fixtures, and three OrganizationMembership episode fixtures inside an explicit transaction. The transaction was rolled back after assertions.

| Assertion | Fresh | Staged |
|---|---|---|
| Valid User and Organization parents support a valid OrganizationMembership insert | PASS | PASS |
| A second `ACTIVE` slot for the same User is rejected by `organization_membership_user_slot_key` | PASS | PASS |
| A `SUSPENDED` slot for the same User while an `ACTIVE` slot exists is rejected by the same partial unique index | PASS | PASS |
| Missing User is rejected by `organization_membership_userId_fkey` | PASS | PASS |
| Missing Organization is rejected by `organization_membership_organizationId_fkey` | PASS | PASS |
| Updating a referenced User primary key is rejected by the User FK | PASS | PASS |
| Deleting a referenced User is rejected by the User FK | PASS | PASS |
| Updating a referenced Organization primary key is rejected by the Organization FK | PASS | PASS |
| Deleting a referenced Organization is rejected by the Organization FK | PASS | PASS |
| Parent and membership fixture state remains intact after rejected operations | PASS | PASS |
| Transaction rollback completed | PASS | PASS |
| Post-rollback residual User, Organization, and Membership counts are all zero | PASS | PASS |

The accepted fixture state contained one `ACTIVE`, one `REVOKED`, and one `ENDED` episode for the same User across three Organizations. This confirms that multiple terminal historical episodes can coexist while the one-current-slot partial unique index remains in force. It does not establish a complete membership lifecycle or authorization behavior.

Both targets reported `ACTIVE = 1`, `REVOKED = 1`, and `ENDED = 1` before rollback. Post-rollback counts were `residual_users = 0`, `residual_organizations = 0`, and `residual_memberships = 0`. All SQL assertion blocks completed successfully on both targets.
